# 만사모 백엔드 참고 서류

## 1. 현재 구현 상태

### 이미 백엔드에 구현된 기능

- Node.js `node:http` 기반 API 서버
- SQLite 기반 회원 및 세션 저장
- 회원가입, 로그인, 내 정보 조회 및 수정
- 비밀번호 `scrypt` 해시
- Bearer 토큰 인증 및 만료 시간 검사
- OpenAI Responses API 연결
- AI 기능 7종
  - 스토리·캐릭터·세계관 상담
  - 3막 구조 제안
  - 장면 가이드
  - 캐릭터 설정 충돌 검사
  - 복선 점검
  - 세계관 정리
  - 내보내기 요약
- AI 입력 길이, 출력 토큰, 시간당 호출 횟수 제한
- API 키 서버 환경변수 관리 및 `store: false` 적용

관련 파일:

- `backend/src/server.mjs`
- `backend/src/openai.mjs`
- `backend/.env.example`
- `frontend/src/api/ai.api.ts`
- `frontend/src/api/auth.ts`

### 아직 프론트엔드 localStorage에 저장되는 기능

- 프로젝트
- 캐릭터
- 회차
- 복선
- 3막 구조
- 세계관과 장소 참고 이미지
- 할 일 체크리스트
- 작업 일정 타임라인
- 인물관계도 노드·연결선·메모

현재 임시 저장소는 `frontend/src/mocks/store.ts`이다. 실제 배포 전에는 아래 API와 DB로 교체해야 한다.

## 2. 권장 기술 결정

### 데이터베이스

개발 환경에서는 SQLite를 유지할 수 있지만 실제 서비스는 PostgreSQL 사용을 권장한다.

이유:

- Render, Railway 등의 무료·임시 파일시스템에서는 SQLite 파일이 재배포 시 유실될 수 있음
- 동시 쓰기와 백업, 확장성에 PostgreSQL이 적합
- 현재 `node:sqlite`는 실행 환경의 Node 버전에 영향을 받음

ORM은 Prisma 또는 Drizzle 중 하나를 선택한다. 어느 것을 선택하든 마이그레이션 파일을 Git에 포함한다.

### 이미지 저장소

표지와 캐릭터·세계관 이미지를 DB 또는 base64 문자열로 저장하지 않는다.

- 권장: S3, Cloudflare R2, Supabase Storage 등 객체 저장소
- DB에는 파일 URL, 파일 키, 크기, MIME 타입만 저장
- 업로드 시 MIME 타입과 실제 파일 내용을 모두 검사
- 이미지당 크기와 해상도 제한 적용

## 4. 반드시 서버에서 강제할 제한

프론트 제한은 우회할 수 있으므로 동일한 검증을 DB 트랜잭션 안에서 실행한다.

- 사용자당 프로젝트 최대 10개
- 프로젝트당 캐릭터 최대 100명
- 완결 목표 1~900화
- 현재 회차 0~완결 목표
- 개별 회차 번호 1~해당 프로젝트의 완결 목표
- 프로젝트 안에서 회차 번호 중복 금지
- 복선 등장화 1~완결 목표
- 복선 회수화는 등장화 이상이며 완결 목표 이하
- 세계관 장소 이미지 최대 3장
- 프로젝트 삭제 시 연결 데이터와 이미지 함께 삭제
- 프로젝트의 완결 목표를 줄일 때 기존 현재 회차·등록 회차·복선 범위를 침범하면 거절

프로젝트와 캐릭터 개수를 확인한 뒤 생성하는 과정은 반드시 하나의 트랜잭션으로 묶어 동시 요청으로 제한이 뚫리지 않게 한다.

## 6. 프론트엔드 연결 지점

백엔드 API가 완성되면 아래 파일에서 mock store 호출을 `apiClient` 호출로 교체한다.

- `frontend/src/api/projects.ts`
- `frontend/src/api/characters.ts`
- `frontend/src/api/story.ts`
- `frontend/src/api/worldSettings.ts`
- `frontend/src/api/todos.ts`
- `frontend/src/api/timeline.ts`
- `frontend/src/api/relationshipBoards.ts`

현재 타입 계약은 다음 파일에 있다.

- `frontend/src/types/index.ts`
- `frontend/src/types/ai.ts`

응답 JSON 필드명을 가능하면 현재 TypeScript 타입의 camelCase와 동일하게 유지하면 프론트 수정량이 줄어든다. DB의 snake_case는 API 직렬화 단계에서 변환한다.

`frontend/src/api/schedule.ts`의 마감 확률 계산은 현재 순수 계산식이다. 같은 결과를 여러 기기에서 유지해야 한다면 서버로 이전하고, 아니라면 프론트 계산으로 유지해도 된다.

PDF 내보내기는 현재 브라우저에서 생성되므로 백엔드 필수 작업이 아니다. 서버 보관·메일 전송·공유 링크가 필요할 때만 별도 PDF 작업을 추가한다.

## 7. 기존 localStorage 데이터 이전

기존 사용자의 데이터를 보존하려면 일회성 가져오기 API를 만든다.

권장 흐름:

1. 로그인 후 서버에 프로젝트가 없고 localStorage 데이터가 있을 때만 이전 안내 표시
2. `POST /api/migrations/local-import`에 프로젝트와 하위 데이터를 한 번에 전송
3. 서버에서 소유권, 개수, 회차, 중복, 이미지 크기를 다시 검증
4. 트랜잭션으로 전체 저장
5. 서버 성공 응답을 받은 뒤에만 localStorage를 백업 또는 삭제
6. `migration_id` 또는 사용자별 이전 버전으로 중복 실행 방지

촬영용 가상 작품 2개는 일반 사용자 데이터와 분리한다. 운영 DB에 넣는다면 `is_demo` 플래그를 두거나 데모 계정에만 시드한다.

## 8. 인증·보안 보완

- 모든 하위 리소스에서 프로젝트 소유권 확인
- CORS 허용 주소를 `FRONTEND_ORIGIN` 환경변수로 설정
- 운영 환경에서는 `0.0.0.0`으로 서버 바인딩
- HTTPS 강제
- Helmet 수준의 보안 헤더 적용
- 로그인, 회원가입, AI, 업로드 API에 영구적인 rate limit 적용
- 현재 메모리 기반 AI rate limit은 재시작 또는 여러 인스턴스에서 공유되지 않으므로 Redis나 DB로 이전
- JSON body와 업로드 파일 크기 제한
- 사용자 입력을 로그에 그대로 남기지 않기
- SQL은 항상 파라미터 바인딩 사용
- 키와 DB 접속정보는 배포 서비스의 Secrets에 저장
- 실제 `.env`는 GitHub에 올리지 않기
- 탈퇴 기능 구현 시 프로젝트·파일·세션을 함께 삭제

## 9. OpenAI 비용 보호

현재 연결은 동작하지만 운영 전 다음을 추가한다.

- 만사모 운영 전용 OpenAI 프로젝트와 API 키 사용
- OpenAI 프로젝트 지출 한도 및 알림 설정
- 사용자별·일별 AI 호출 제한을 DB 또는 Redis에 저장
- `response.usage`를 `ai_usage_events`에 기록
- 기능별 최대 출력 토큰 유지
- 대화 기록은 최근 필요한 범위만 전송
- 모델명은 환경변수로 유지
- OpenAI 장애·429·타임아웃에 사용자 친화적 오류와 제한된 재시도 적용
- 프롬프트 원문, API 키, 작품 전체 내용을 운영 로그에 기록하지 않기

## 10. 배포 환경변수

최소 권장 값:

```text
NODE_ENV=production
PORT=<배포 플랫폼 제공값>
HOST=0.0.0.0
FRONTEND_ORIGIN=https://실제-프론트-도메인
DATABASE_URL=<PostgreSQL 연결 주소>
OPENAI_API_KEY=<배포용 키>
OPENAI_MODEL=gpt-5.6-luna
OPENAI_MAX_OUTPUT_TOKENS=700
OBJECT_STORAGE_ENDPOINT=<선택>
OBJECT_STORAGE_BUCKET=<선택>
OBJECT_STORAGE_ACCESS_KEY=<선택>
OBJECT_STORAGE_SECRET_KEY=<선택>
```

프론트 배포 환경에는 다음 값만 둔다.

```text
VITE_API_URL=https://실제-백엔드-도메인
```

`VITE_` 환경변수에는 비밀키를 절대 넣지 않는다.

## 11. 배포 전 필수 수정

현재 `server.mjs`는 다음 부분이 로컬 개발 기준이다.

- CORS가 localhost만 허용
- 서버가 `127.0.0.1`에 바인딩
- SQLite 데이터가 로컬 파일에 저장
- DB 마이그레이션 도구가 없음
- AI rate limit이 메모리에만 저장
- 로그아웃 및 세션 철회 API가 없음

이 항목을 해결하지 않고 배포하면 프론트에서 API가 막히거나, 재배포 시 데이터가 사라지거나, 여러 서버 인스턴스에서 제한이 일관되지 않을 수 있다.

### 1단계: 배포 기반

3. 프로젝트 테이블과 소유권 미들웨어 구현
4. 공통 오류 응답과 입력 검증 도입

1. 프로젝트 CRUD

4. 세계관·할 일·타임라인 CRUD

### 3단계: 파일과 이전

1. 객체 저장소 연결
2. 표지·캐릭터·세계관 이미지 업로드

### 4단계: 운영 안정화

1. 영구 rate limit과 AI 사용량 기록
2. DB 백업과 복구 테스트
3. 모니터링, 오류 추적, 구조화 로그
4. 통합 테스트와 권한 테스트
5. 스테이징 배포 후 프론트 연결

## 13. 완료 기준

- 다른 사용자 프로젝트 ID를 직접 입력해도 조회·수정·삭제할 수 없음
- 프로젝트 11번째, 캐릭터 101번째 생성이 서버에서 거절됨
- 901화와 중복 회차가 서버에서 거절됨
- 프로젝트 삭제 시 하위 DB 데이터와 저장소 이미지가 함께 삭제됨
- 새 브라우저 또는 다른 기기에서 로그인해 같은 데이터를 확인할 수 있음
- 재배포 후에도 데이터가 유지됨
- API 키가 프론트 번들, Git, 로그에 없음
- OpenAI 호출량과 비용을 사용자·기능별로 확인할 수 있음
- PostgreSQL 백업본으로 복구 테스트가 완료됨
- 프론트 프로덕션 빌드가 실제 백엔드 도메인과 정상 통신함
